Crystamber Architecture

How a tap on a card turns into a saved collection. There is no server of our own: a static web app on Vercel at crystamber.com, data and sign-in on Supabase, account emails through Resend, and GitHub for shipping.

crystamber.com · repo nelsenafc/Crystamber · as of 13 Oct 2026

How a tap gets saved

  1. You tap a card. It is written to localStorage straight away and the screen updates, online or not.
  2. That set is queued. A moment later the app upserts one row in user_sets for that set only, so a bad write can never touch your other sets.
  3. If you are offline or the write fails, the set stays queued and retries, backing off up to 30 seconds.
  4. On opening, the app reads your rows before it is allowed to push anything. Each row carries a rev number; if two devices both changed a set, the two sides are merged rather than one erasing the other.

How a change ships

  1. Edit on branch multi-user, syntax-check the page, try it on a local copy.
  2. Push. Vercel builds it and reports the commit status.
  3. Fast-forward main. Vercel puts it live on crystamber.vercel.app.
  4. Open phones see a "new version" prompt from the service worker and refresh in one tap.

Switched off, not deleted

Trades, Group and the trade flag on cards sit behind const SOCIAL = false in index.html. The tables and code are still there; flipping the flag brings all three back if other collectors join.

Known limits

LimitStatusWhat it means
Free-tier pauseHandledSupabase pauses idle free projects. It happened twice; a daily write ping replaced the old read ping on 11 Oct.
Email confirmation offIn progressSign-ups go straight in, and Supabase's built-in mailer only reaches its own team. The domain is in place; Resend is being connected so resets reach everyone, then confirmation goes back on.
Card art and symbolsBefore chargingThey belong to Nintendo and The Pokémon Company. Fine for a free fan tool; needs a plan before any paid version.
No automated testsWatchEvery release is syntax-checked and tried on a local copy first. The service worker keeps whatever page it last fetched, so a broken release would stick on phones until the next one.
